# Brief — `ci/flutter-release`

**Kind:** layer · **Issue:** #14 (parent #2) · **Cookbook:** `#env`, `#cicd`

Layer (file-routed) for the config files. The *procedures* around it — release management,
store submission, certificates, build triage — are separate commands.

## Globs
```yaml
paths:
  - ".github/workflows/*.y*ml"
  - "android/**/build.gradle*"
  - "android/**/AndroidManifest.xml"
  - "ios/**/*.plist"
  - "ios/**/project.pbxproj"
  - "**/.env_*"
  - "**/analysis_options.yaml"
```

## Rules to encode
1. **Flavor selection has one mechanism per side, and they are different switches.**
   `--flavor` selects the native Gradle/Xcode flavor; `--dart-define=FLAVOR=` selects the
   Dart config. Setting one does not set the other. **Never a `defaultValue`** — a missing
   define must fail the build, or a misconfigured release silently ships pointing at dev.
2. Startup logs and asserts the resolved flavor and API host; sets them as crash keys.
3. Non-production flavors get an `applicationIdSuffix` / bundle-ID suffix, their own name
   and a distinguishable icon, so QA and prod install side by side.
4. Pin every SDK in-repo and match it in CI — Flutter (`.fvmrc`), JDK, Xcode, CocoaPods.
   `minSdk`/`targetSdk`/`compileSdk` and the iOS deployment target as explicit integers,
   never `flutter.minSdkVersion`.
5. Four required PR checks: `dart format --set-exit-if-changed`,
   `flutter analyze --fatal-infos --fatal-warnings`, `flutter test --coverage`, and
   lockfile-honouring resolution. `--fatal-infos` is load-bearing — without it most lints
   report at info level and pass silently.
6. The gate stays under ten minutes and runs on Linux. iOS builds on merge, not in the gate.
7. CI asserts its own inputs — env files non-empty, codegen output unchanged
   (`git diff --exit-code`) — so a missing secret fails with a message naming it.
8. Version name and build number generated by CI and monotonic. Nothing built or uploaded
   from a developer machine.
9. Release builds obfuscate **and** upload symbols in the same job.
10. Runner images pinned, not `-latest`. Secrets masked, written via `base64 -d`, never echoed.
11. `analysis_options.yaml` carries `strict-casts`, `strict-inference`, `strict-raw-types`,
    `use_build_context_synchronously: error`, `always_use_package_imports`,
    `prefer_const_constructors`, `avoid_print`.

## Eval cases
*Assertions below are sketches of intent, not literal strings. Replace any prose
with a discriminating code token — see AUTHORING.md section 6.*

| id | Scenario | must_contain | must_not_contain |
|---|---|---|---|
| 01 | A release build step for the prod flavor | `--dart-define=FLAVOR=`, `--obfuscate`, `--split-debug-info` | `--flavor prod` alone |
| 02 | Read the flavor in Dart | `String.fromEnvironment('FLAVOR')`, a throw on absent | `defaultValue:` |
| 03 | The PR gate workflow | `--fatal-infos`, `--set-exit-if-changed`, `git diff --exit-code` | `flutter analyze` bare |
| 04 | `analysis_options.yaml` for a new app | `strict-casts`, `use_build_context_synchronously` | lints without `errors:` |

## Boundaries
Signing credentials and store accounts are the `/flutter-signing` command. Build failure
triage is `/flutter-build-doctor`.
