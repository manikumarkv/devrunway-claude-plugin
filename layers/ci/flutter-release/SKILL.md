Full standards in [flutter-release.md](flutter-release.md). Always-on summary:

**Scope:** the build configuration files and the workflows that consume them. Signing credentials and store accounts are the `/flutter-signing` command; build-failure triage is `/flutter-build-doctor`; logger and crash-reporter implementation is `logging/flutter-observability`.

**Flavor — two switches that look like one:**
- Every build command passes **both** `--flavor <name>` (native application id, icon, signing) and `--dart-define=FLAVOR=<name>` (the Dart-side config). Setting one does not set the other, and nothing about a half-configured build looks wrong.
- Dart reads `const String.fromEnvironment('FLAVOR')` with **no fallback** and throws when it is empty. A build that forgets the define must fail, not quietly pick a config.
- Bootstrap asserts the resolved flavor, logs it together with the resolved API host, and sets both as crash keys alongside app version and build number.
- Every non-production flavor gets its own `applicationIdSuffix`, display name and launcher icon, so QA and production install side by side on one device and are distinguishable once installed.
- The display name is supplied per flavor as `resValue("string", "app_name", …)` and the shared manifest references it as `android:label="@string/app_name"`. A literal label in the shared manifest silently wins over every per-flavor value, and all flavors end up named alike.

**Pinned toolchain:**
- Flutter version in `.fvmrc`; JDK, Xcode and CocoaPods versions pinned in-repo, and CI reads those same files rather than restating the numbers.
- `minSdk`, `targetSdk`, `compileSdk` and `IPHONEOS_DEPLOYMENT_TARGET` are explicit integers in the Gradle and Xcode config, never inherited from the Flutter Gradle plugin's forwarded properties — an inherited value changes which devices you support on a toolchain upgrade, with no diff.

**The PR gate — four required checks, Linux only, under ten minutes:**
- `dart format --output=none --set-exit-if-changed .`
- `flutter analyze --fatal-infos --fatal-warnings` — without `--fatal-infos` most lints report at info severity and pass silently, which makes a strict `analysis_options.yaml` decorative.
- `flutter test --coverage`
- Resolution that honours the committed lockfile: `flutter pub get --enforce-lockfile`.
- iOS builds on merge, not in the gate — a macOS runner minute costs roughly ten Linux minutes.

**CI asserts its own inputs, before it builds:** each generated env file is checked non-empty **by name** with `[ -s .env_<flavor> ]`, and codegen is re-run then verified with `git diff --exit-code` over the generated paths — so a missing secret or stale generated code fails immediately with a message naming it, instead of surfacing as a confusing generator error minutes later. An assertion step is never allowed to be waved through: no flag or suffix that lets it fail without stopping the run.

**Release:** version name and build number are generated by CI and monotonic; nothing is built or uploaded from a developer machine. A release build passes `--obfuscate` **and** uploads the `--split-debug-info` output in the same job — obfuscating without uploading trades readable binaries for unreadable crash reports. Runner images pinned to a dated label. A binary or multiline secret arrives via `env:` and is written with `base64 -d` into a file — never echoed, and never interpolated into a `run:` body, where the value lands on the process command line.

**`analysis_options.yaml` (this layer owns the canonical file):** `strict-casts`, `strict-inference`, `strict-raw-types`; `use_build_context_synchronously: error` and `avoid_print: error` under `analyzer.errors`; `always_use_package_imports` and `prefer_const_constructors` under `linter.rules`; `invalid_annotation_target: ignore` for freezed; generated files excluded.
